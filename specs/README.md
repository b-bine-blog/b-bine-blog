# specs

[Spec Kit](https://github.com/github/spec-kit) 형식의 기능 명세입니다. 요구사항분석서(`docs/`)를 모듈별로 나눠 사용자 스토리, 인수 시나리오(Given/When/Then), 기능 요구사항(FR), 성공 기준으로 옮겼습니다.
각 FR 끝의 `[USR-02, 6.7, D-42]` 같은 표시가 원본 요구사항 ID·세부 정책·결정 번호이고, 명세마다 원본 ID → FR 추적표가 있습니다.

## 확인 필요 항목

문서에 없거나 문서끼리 맞지 않는 부분은 지어내지 않고 `[NEEDS CLARIFICATION: …]`으로 남겼습니다. 규칙을 정하면 `/speckit-clarify`로 명세에 반영하고, 결정이면 `docs/03-decisions/`에 D-번호를 추가합니다.

먼저 정하면 좋은 것(여러 명세에 걸치거나 문서끼리 충돌하는 항목):
- 2장 권한 표는 메인 관리자의 "참여 승인·멤버 강퇴"를 O로 적었지만 ADM-01·D-44는 메인 관리자가 블로그장 강퇴와 블로그 폐쇄만 한다고 함 (002, 005)
- SEC-09 "관리자 계정은 일반 회원과 분리"가 별도 계정인지, 회원 계정에 권한을 붙이는 것인지 (005)
- 블로그장이 자기 블로그에 쓴 글·댓글, 메인 프로필에서 한 회원 신고를 누가 처리하는지 (003, 005)
- 메인 관리자가 블로그를 강제 폐쇄할 때 즉시인지, 7일 뒤 04:00인지, 철회는 누가 하는지 (002, 005)
- 경고·정지 횟수를 블로그별로 세는지 사람별로 세는지, 1년 보관 기간과의 관계 (002, 005)
- "인기순"의 기준(조회수·좋아요·구독자 등) (002, 004)
- 6.4 태그 금칙어(보류) (004)
